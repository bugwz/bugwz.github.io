# 观我 ScaleMe: 一款兼容多设备的体重记录 App

家里先有一台小米体重秤 2, 后来又白嫖了一台蚂蚁阿福联名体脂秤. 两台秤各用各的 App, 用着都不太顺手, 于是我做了观我 ScaleMe, 想把不同设备和家人的测量记录放到一起, 方便查看体重和体脂的变化.

想先试试的话, 可以用 iPhone 扫描下面的二维码, 或直接点击 [App Store 下载观我](https://apps.apple.com/app/id6808930548). 应用需要 iOS 17 或更新版本.

![观我应用与体重秤, 扫描右侧二维码前往 App Store 下载](/assets/images/posts/scaleme/download-banner-v4.webp)

# 1. 为什么做这款应用

最开始家里有一台小米体重秤 2, 后来又参加活动领到了一台蚂蚁阿福联名体脂秤. 两台秤都有各自配套的 App, 测量记录也分别存在里面. 想看看之前的数据, 还得想一下那次用的是哪台秤, 再打开对应的应用.

小米这类应用要照顾整个设备生态, 除了体重秤, 还要管理手表等设备, 功能自然就多了. 这些功能对有需要的人有用, 但我打开它, 大多数时候只是想记一下体重, 看看之前的数据. 为了这么一点需求, 用一个功能很杂的应用, 总觉得有些费劲.

蚂蚁阿福的体脂秤入口又比较深, 要在 App 里找. 再加上有的应用有广告, 有的需要登录, 只是称个重, 看看记录, 操作起来却有些麻烦.

于是就有了一个念头: 能不能 **用同一个 App 连接这些体重秤和体脂秤**? 不管这次踩的是哪台秤, 记录都能放在一起; 家里不同的人称完, 也能各自看到自己的变化.

**观我** 就是从这个念头开始做的, 英文名叫 **ScaleMe**. 它是一个原生 iOS 应用, 用 Swift 和 SwiftUI 编写, 最低支持 iOS 17.

我最初想的是尽量把各种秤都接进来. 不过, 这是希望逐步做到的事, 当前还不能说所有体重秤都能用. 具体型号的适配情况, 后面会单独说.

# 2. 目前应用支持的功能

现在的主要功能, 可以先看这张表. 后面再跟着界面走一遍.

| 功能 | 具体用法 |
|:---:|---|
| 多设备管理 | 添加兼容的蓝牙体重秤和体脂秤, 保留每条记录的设备来源 |
| 多成员档案 | 分别保存家人的资料和测量记录, 按成员查看, 归错人的记录可以修改 |
| 蓝牙测量与手动录入 | 查看本次称重的读数和完成状态, 没有连接设备时也能自己填写记录 |
| 历史记录 | 对支持的设备读取秤内历史, 去重并尝试匹配成员, 查看详情或删除记录 |
| 趋势分析 | 按指标, 时间, 设备和成员筛选, 切换逐次测量与日, 周, 月汇总, 支持点位查询和全屏图表 |
| 本地保存与备份 | 无需注册或联网, 数据保存在本机, 支持配置与测量记录的 JSON 导入导出 |
| Apple 健康同步 | 按需开启体重和体脂率的共享与获取, 将同步范围限定在本人 |
| 桌面小组件 | 提供小, 中, 大三种尺寸, 独立配置成员, 指标和时间范围 |
| 外观与无障碍 | 支持浅色, 深色及跟随系统, 提供色觉友好主题, 10 种界面语言和 VoiceOver 支持 |

设备能提供哪些测量指标, 是否能读取历史, 仍要看具体协议的适配情况. 表里的功能不代表每台秤都具备这些能力.

# 3. 界面与操作

应用底部有 5 个入口:

- **首页:** 查看各成员最近一次的测量数据和健康指标.
- **测量:** 选择设备和成员, 开始测量或手动录入数据.
- **趋势:** 按成员, 设备和时间查看历史记录与指标变化.
- **设备:** 扫描添加蓝牙设备, 管理已添加的体重秤和体脂秤.
- **设置:** 管理成员资料, 调整外观, 数据和健康同步等选项.

下面是应用的界面截图. 图中的成员, 设备和读数为演示数据.

## 3.1 首页

首页展示 **当前成员最近一次的测量数据和个人卡通形象**. 卡通形象可以在成员设置里选择. 左右滑动卡片, 可以查看应用里其他人的数据, 背景颜色也会随着成员切换而变化.

卡片下方的健康指标跟随当前成员显示, 比如体脂率, 肌肉量和水分. **可以调整指标顺序, 也可以选择显示或隐藏哪些指标**, 把自己关心的数据放在前面. 点击 "开始测量" 就能进入测量页.

![观我首页, 成员卡片与健康指标](/assets/images/posts/scaleme/home-current.webp)

指标以已有数据为准. BMI 可以根据身高和体重计算, 脂肪量可以根据体重和已有体脂率换算, 但应用不会单凭阻抗补算体脂, 骨量或基础代谢. 身体成分数据用于趋势参考, 不作为医疗诊断依据.

## 3.2 测量

**在测量页选择设备和成员**, 就可以开始称重. 页面中间显示本次体重和测量状态, 收到本次蓝牙数据前显示占位符. 完成后, 下方会列出这次测量的时间, 指标, 设备和成员, 可以进入详情查看.

![观我测量页, 本次读数与测量结果](/assets/images/posts/scaleme/measure-current.webp)

没有连接设备或需要补记录时, 可以使用 "手动录入数据". 测量详情里也能修改成员归属或删除记录.

## 3.3 趋势

趋势页可以查看不同成员, 不同设备的历史数据, 也可以把 **同一个人来自多台设备的记录放在一起看**. 体重, BMI, 体脂率等指标分别展示, 顶部可以选择类别, 时间, 设备, 用户和显示方式.

![观我趋势页, 筛选入口与不同指标的曲线](/assets/images/posts/scaleme/trends-current.webp)

"逐次测量" 保留每次测量的点位和实际时间间隔; "汇总趋势" 则根据时间跨度, 聚合为日, 周或月均值. 每个数据块右上角都有放大按钮, 点击后可以 **横屏全屏查看图表**, 查询具体点位.

桌面小组件也可以看趋势, 有小, 中, 大三种尺寸, 可以独立配置成员, 指标和时间范围, 不会影响应用里的图表设置.

## 3.4 设备

观我通过蓝牙连接体重秤和体脂秤. 设备页列出已经添加的设备及其匹配状态, 可以为它们设置容易区分的名称, 再进入详情查看具体信息和可用设置.

![观我设备页, 多台设备与协议匹配状态](/assets/images/posts/scaleme/devices-current.webp)

点击 "添加设备" 后, 应用会扫描附近的蓝牙设备, **根据内置通信协议的匹配条件识别候选体重秤**, 把能识别的设备列在推荐区域. 没有识别出来的设备, 可以展开 "其他附近蓝牙设备" 查看和管理.

推荐识别只是协议匹配的结果, 具体能用哪些功能仍要看型号的适配和验证情况. 支持读取历史的设备可以导入秤内记录, 应用会去重并尝试匹配成员; 已删除的设备记录也会通过最小标记避免重复导入.

## 3.5 设置

**设置页可以管理多位成员**, 修改名称, 角色, 性别, 出生日期和身高等信息, 并为每个人选择卡通形象. 这些资料用于区分记录归属和计算相应指标.

![观我设置页, 用户信息与各项设置入口](/assets/images/posts/scaleme/settings-current.webp)

常用设置分在几个入口里:

- **显示设置:** 选择浅色, 深色或跟随系统的外观, 也有针对色觉辨识需求的色觉友好主题. 这里还可以调整语言, 体重单位和是否合并连续称重.
- **数据管理:** 导入或导出配置与测量记录, 开启模拟数据浏览界面, 或经过确认后删除所选数据.
- **Apple 健康同步:** 按需授权并开启体重和体脂率的共享与获取.
- **通信协议:** 查看内置协议及其状态, 或从本地文件导入外部通信规则.
- **关于应用:** 查看应用信息和隐私政策.

**应用还支持 VoiceOver**, 测量状态可以主动播报, 趋势图提供可探索的数据描述, 大字体下的布局也会相应调整.

# 4. 两台秤的适配经历

最初促使我做这个应用的两台秤, 在适配时也刚好碰到了两种不同的处理方式. 都是通过蓝牙通信, 但测量数据怎么返回, 历史记录读完后还在不在, 并不一样. 下面说的是我手上这两款设备的适配经历.

## 4.1 小米体重秤 2

小米体重秤 2 只能称体重, 没有后面的体脂测量过程, 所以测量数据相对简单. 适配时除了接收当前读数, 还需要区分数值是否稳定, 用户是否已经离秤.

适配时发现, 比较有意思的是它的历史记录. 秤内会保存一些之前的测量, 可以通过蓝牙拉取. 而且 **读完之后, 这些记录仍然留在秤里**, 不会因为已经被某个应用接收过, 就从设备上消失.

项目里的抓包分析也确认了这一点: 在已经发送接收确认的会话之后, 用相同的查询游标仍能再次读到旧记录. 所以这里的确认操作不能理解成清空历史, 应用自己还要处理重复导入的问题. 适配其他秤时, 也不能直接套用这台秤的历史查询和接收确认流程.

这对换应用很有用. 即使之前用其他应用读过, 只要记录还保存在秤里, 就仍有机会重新拉取到 ScaleMe 中. 当然, 这也不意味着秤会永久保存所有记录.

另外, 小米体重秤 2 的 **显示单位也能通过蓝牙修改, 支持千克, 斤和磅**. 这里改的是秤本身屏幕上的单位, 与只在手机里换算显示是两件事. 项目为它实现了单独的单位设置命令.

## 4.2 蚂蚁阿福联名体脂秤

这台蚂蚁阿福联名体脂秤是当时参加活动薅到的. 记得好像只要付 9.9 元运费, 就能领一台. 拿到手才发现, 它得配合蚂蚁阿福 App 使用, 而且体脂秤的入口藏得比较深. 我只是想称个重, 看看记录, 还得在里面找入口, 这也让我更想做一个单独的应用来用这些秤.

适配时发现, 它的测量过程比小米那台多了一段.

站上去之后, 先能拿到体重. 这时还不能马上下秤, 要继续站一会儿, 等体脂检测完成, 体脂率等身体成分数据才会传过来. 从应用接收数据的角度看, 可以把它理解成两个阶段: **先收到体重, 再收到体脂率等身体成分数据**, 一次测量的数据分批到达.

因此, 收到稳定体重时还不能结束整次测量, 得继续等待体脂率等数据到齐, 再保存完整的测量记录.

它的历史记录处理也和小米不同. 这台秤同样会在机内保存一些测量记录, 但按我这次适配中观察到的行为, **应用完成接收后, 相应记录就不再留在秤内供后续应用重新读取了**.

这会直接影响换应用的过程. 比如之前一直用蚂蚁阿福 App 称重, 记录已经被它接收了. 后来换成 ScaleMe, 可以继续记录之后的测量, 但再去读秤内历史, 就拿不到那些已经传给旧应用的数据.

这时, 单靠重新连接蓝牙没法把旧记录找回来. 如果旧应用里还留着数据, 可以对照它的记录, **用 ScaleMe 的手动录入补进来**. 所以, 支持读取秤内历史, 并不等于能自动迁移另一个 App 里保存的全部历史. 这两台秤的测量阶段和历史记录处理方式不同, ScaleMe 也需要按各自的协议分别适配.

# 5. 源码与参考项目

源码公开在 [GitHub 的 ScaleMe 仓库](https://github.com/bugwz/ScaleMe), 采用 GPL-3.0-or-later 许可证.

适配这些秤时, 我参考了社区已有的协议实现, 逆向分析和蓝牙数据样本. 其中主要有两个项目:

- **[openScale](https://github.com/oliexdev/openScale):** 一个支持蓝牙体重秤和体脂秤的开源 Android 应用. ScaleMe 的华为 Hagrid/WSP 及多个广播协议解析器参考或改编了它的实现, 小米秤的协议研究也参考了它的 Wiki.
- **[ble-scale-sync](https://github.com/KristianP26/ble-scale-sync):** 一个读取蓝牙秤数据并同步到其他服务的开源项目. ScaleMe 的小米 XMTZC04HM 和 Silvergear 108 广播解析参考或改编了它的实现, 也参考了对应的测试数据样本.

这些资料帮助我理解不同型号的数据格式和通信过程, 再结合手上设备的抓包记录做适配. 这里参考的 "数据" 是协议报文和测试样本, 不是其他用户的体重或体脂记录. 具体来源, 文件对应关系和第三方声明保存在仓库的 `LICENSES/` 目录中.

**参考了上游实现, 不代表上游支持的所有型号都已经在 ScaleMe 中验证.** 各型号的适配状态记录在 `Docs/BluetoothProtocolSupport.md` 中, 可以按具体型号查看. 样本解析通过, 也不等于完整的 iPhone 测量流程已经验证.

想自己编译的话, 用 Xcode 26 或更新版本打开 `ScaleMe.xcodeproj`. 模拟器可以配合设置中的模拟数据浏览多成员记录和趋势图; 蓝牙测量与 HealthKit 授权需要签名安装到 iPhone 上验证.
